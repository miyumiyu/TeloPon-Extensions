# 🌉 Мост TeloPon (TeloponBridge.py)

📥 **[Скачать TeloponBridge.py](https://raw.githubusercontent.com/miyumiyu/TeloPon-Extensions/main/plugins/TeloponBridge.py)**

Плагин, связывающий два экземпляра TeloPon через HTTP, чтобы **два ИИ могли разговаривать друг с другом**.
Стример играет роль ведущего/фасилитатора, наслаждаясь обменом репликами между двумя ИИ-персонажами.

---

## 🌟 Основные функции

| Функция | Описание |
|---|---|
| Отправка телопов | Перехватывает локальный вывод телопа и отправляет HTTP POST на другой экземпляр |
| Приём телопов | Запускает HTTP-сервер (localhost) для приёма сообщений от другого экземпляра |
| Внедрение в ИИ | Полученные сообщения внедряются в ИИ как `[Мост] {speaker}: {содержимое}` |
| Защита от цикла | Авто-пауза по минимальному интервалу отправки и максимальному числу ходов |
| Пауза/Возобновление | Ручное управление разговором из UI |
| Аддон промпта | Авто-добавляет инструкцию ИИ "это другой ИИ, не комментарий зрителя" |

---

## ⚙️ Принцип работы

```
[Экземпляр A: AI-A] ─ вывод телопа
        ↓ хук on_telop_output
        ↓ HTTP POST → http://localhost:9002/recv
[Экземпляр B: AI-B] ← получает
        ↓ self.send_text(plugin_queue, "[Мост] AI-A: ...")
        ↓ AI-B генерирует ответ → вывод телопа
        ↓ HTTP POST → http://localhost:9001/recv
[Экземпляр A: AI-A] ← получает ... цикл
```

## 📦 Установка

1. Скачайте **«🌉 Мост TeloPon»** из менеджера плагинов расширений
2. Файл будет автоматически размещён по пути `plugins/TeloponBridge.py`
3. Перезапустите TeloPon

## 🛠 Использование (два экземпляра)

### Шаг 1: Подготовьте две папки

Чтобы избежать конфликтов `settings.json`, **скопируйте TeloPon в отдельные папки**:

```
C:\TeloPon-A\   ← Экземпляр A
C:\TeloPon-B\   ← Экземпляр B
```

### Шаг 2: Используйте разные порты

Порт HTTP-сервера для браузер-источника OBS также конфликтует, поэтому установите их отдельно при запуске:

| | Экземпляр A | Экземпляр B |
|---|---|---|
| Запуск | `python telopon.py -p 8000` | `python telopon.py -p 8010` |
| Браузер-источник OBS | http://localhost:8000 | http://localhost:8010 |

### Шаг 3: Настройте плагин моста

Откройте плагин в каждом экземпляре и настройте:

| Настройка | Экземпляр A | Экземпляр B |
|---|---|---|
| Активировать мост | ✅ ВКЛ | ✅ ВКЛ |
| Порт приёма | 9001 | 9002 |
| URL отправки | `http://localhost:9002/recv` | `http://localhost:9001/recv` |
| Своё имя | AI-A | AI-B |
| Мин. интервал отправки (сек) | 5 | 5 |
| Макс. ходов | 0 (без ограничения) или 20 и т.п. | то же |

### Шаг 4: Начните стрим → Запустите разговор

Запустите эфир в обоих экземплярах. Стример инициирует разговор, обращаясь к одной стороне:

> Стример (в микрофон A): «Привет, B-сан!»

→ ИИ A выводит телоп → B получает → ИИ B отвечает → возвращается к A → ... продолжается.

---

## ⚠️ Важно: Защита от обратной связи микрофона

Если оба экземпляра работают на одном ПК, **микрофон B уловит голос ИИ A, вызывая неконтролируемый цикл**.

**Меры (одна обязательна):**

1. **Отключите микрофон B**: запуск с `-mi -1` для режима без микрофона
2. **VB-CABLE или похожее виртуальное аудио** для полного разделения
3. **Запустите на двух разных ПК** (самое безопасное)

Также эффективно отключить голос ИИ A в OBS.

## ⚙️ Настройка

### 1. Откройте панель настроек

Нажмите кнопку **«⚙️ Настройки»** для **«🌉 Мост TeloPon»** в панели «Расширения».

### 2. Параметры

| Параметр | Описание |
|---|---|
| **Активировать мост (ВКЛ / ВЫКЛ)** | Запускает HTTP-сервер приёма + включает отправку телопов |
| **Порт приёма** | Порт, на котором этот экземпляр слушает (например, A: 9001, B: 9002) |
| **URL отправки** | Точка приёма другого экземпляра (например, `http://localhost:9002/recv`) |
| **Своё имя** | Имя, добавляемое при отправке (получается как `[Мост] AI-A: ...`). Имя ИИ-персонажа (`ai_name` из настроек промпта) также отправляется и отображается рядом, например "ТелоПон-тян (AI-A)". Если задано только имя ИИ, отображается просто "ТелоПон-тян". |
| **Мин. интервал отправки (сек)** | Защита от спама. Пропускает отправку, если прошло меньше N секунд |
| **Макс. ходов** | 0 = без ограничения; N (>0) — авто-пауза после N обменов |

### 3. Отображение состояния

| Поле | Значение |
|---|---|
| **Сервер приёма** | Работает / Остановлен / На паузе |
| **Отправлено** | Сообщений отправлено за сессию |
| **Получено** | Сообщений получено за сессию |
| **Ходов** | Накопительный счётчик отправок + получений |

### 4. Кнопки

- **⏸ Пауза / ▶ Возобновить**: Временно останавливает/возобновляет разговор
- **🔄 Сбросить ходы**: Сбрасывает счётчик ходов в 0 (полезно после авто-паузы)

## 🎬 Сценарии использования в стриме

### Радиошоу с ИИ
Два ИИ-персонажа свободно болтают; стример — ведущий, задающий темы.

### Манзай / комедийный дуэт ИИ
Боке + Цуккоми (простак + остряк) разделены между двумя ИИ. Распределите роли в каждом промпте.

### Разговор двух NPC в TRPG
Распределите двух NPC (A и B) между двумя экземплярами для естественного диалога.

### Дебаты ИИ / точка-контрточка
Запустите ИИ «за» и «против» как отдельных персонажей; зрители наблюдают за дискуссией.

### ИИ-учитель + ИИ-ученик
Образовательный контент. Учитель объясняет → ученик задаёт вопросы → стример добавляет контекст.

## 💡 Советы по дизайну промпта

Сделайте **роли явно разными** в промпте каждого экземпляра, чтобы избежать монотонного диалога:

```
Экземпляр A: «Вы — оптимистичный ИИ-помощник, AI-B — ваш друг.
            Ведите живые краткие беседы с ним.»

Экземпляр B: «Вы — вежливый, философский ИИ, AI-A — ваш друг.
            Принимайте лёгкость A, отвечая более глубокой перспективой.»
```

При включении плагина моста в ваш промпт автоматически добавляется следующая инструкция:

> Сообщения от другого ИИ могут приходить в формате: '[Мост] {speaker}: ...'
> Обращайтесь с ними как с собеседником (а не комментарием зрителя) и отвечайте естественно.
> Отвечайте кратко (2-3 предложения). Избегайте длинных монологов и передавайте ход обратно.

## ⚠️ Замечания

- **Только локальная связь**: HTTP слушает только на `localhost` (127.0.0.1). Связь через интернет не поддерживается.
- **Без TLS**: Открытый HTTP. Используйте только на одном ПК или в одной локальной сети.
- **Конфликты портов**: Указание занятого порта приведёт к ошибке запуска сервера. Проверьте логи и попробуйте другой порт.
- **Безудержный разговор**: Макс. ходов = 0 (без ограничения) означает бесконечный чат. Рекомендуется устанавливать разумное значение (20-50) во время стримов.
- **Применение изменений настроек**: После изменения порта/URL нажмите «Закрыть» — сервер автоматически перезапустится.

---

## 🔧 Устранение неполадок

| Симптом | Решение |
|---|---|
| Сервер приёма не запускается | Порт может быть занят. Попробуйте другой (например, 9011) |
| В логах «отправка не удалась» | Другой экземпляр не запущен или неверный URL отправки |
| Разговор идёт бесконечно | Нажмите паузу или установите лимит максимальных ходов |
| ИИ повторяются | Уточните промпт «отвечать кратко» или увеличьте интервал ходов |
| Обратная связь микрофона | Используйте виртуальное аудио для разделения или отключите один микрофон |
